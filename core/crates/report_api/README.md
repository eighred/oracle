# Portfolio report API

The local Vue workstation reads a versioned envelope containing the dated risk report and the full net-of-cost backtest. The publishing command uses the same Rust domain functions as the financial CLIs. PostgreSQL stores the exact serialized bytes. A check constraint binds their SHA-256 to the report ID. Repeated publication preserves the original row. A reader can request the latest publication or an immutable ID at `GET /api/portfolios/{portfolio}/reports/{version}`. The response supplies the digest in `x-oracle-report-id`.

The [migration](migrations/001_workstation.sql) defines separate writer and reader roles, expiring sessions, access grants and forced row-level security. Publishing uses `oracle-report-api publish-synthetic` with a writer connection. Serving uses `oracle-report-api serve WEB_DIST` with a reader connection. The API reads `ORACLE_DATABASE_URL` and binds to loopback on `ORACLE_PORT` (default 8040). The database connection supports a Unix socket or numeric loopback IP. This local pilot uses the browser's HTTP Basic prompt over loopback. The operator chooses a temporary passphrase at a masked prompt. PostgreSQL holds a 16-byte random salt and a PBKDF2-HMAC-SHA256 verifier with 600,000 iterations per principal. The browser checks use randomly generated temporary passphrases. Do not expose this development listener through a public reverse proxy.

Each GET checks the credential and portfolio grant in a read-only transaction on a shared connection. The session settings last for that transaction. Database policies also evaluate the grant at row access. The API verifies the digest before returning bytes and disables HTTP caching. Invalid or expired credentials yield 401, denied portfolio scope yields 403, and an authorized missing report yields 404. The reader has no table grants on session credentials or portfolio grants.

Use the [web runbook](../../../web/README.md) to launch the disposable integration or reproduce its verification. On a fresh pilot cluster, `pg_dump` and `pg_restore` into a second database preserve report bytes, session expiry and grants. Cluster roles are shared between the databases for this test. Recovery to a new estate would require restoring roles separately. A lost database connection requires restarting the local API. The synthetic fixture, loopback authentication and cluster restore establish development behavior only.

## Forward paper journal

The [paper migration](migrations/002_paper.sql) follows the workstation migration. PostgreSQL owns the frozen manifest, receipts, committed next instructions and simulated postings. A paper operator can read and append journal entries. The report writer can replay the journal and publish its terminal projection. The browser reader sees published bytes through the existing portfolio policy. Historical and paper reports have separate latest and immutable routes.

Use `oracle-report-api paper freeze FIRST_MS` before the first scheduled UTC minute. The nine-sample manifest fixes the instrument, price generator, three warm-up samples, six settlement opportunities, starting balances, rule set, cost model, acceptance, receipt deadline and source fingerprint of the pricing and decision engine. The operator invokes `paper sample FIRST_MS INDEX` once per minute, with zero-based indices. The synthetic source draws a new uniform price in whole cents between 23 and 27 USDT at receipt. Every journal entry atomically records that observation, the portfolio projection and any instruction for the next minute. Replay checks each posting against the instruction from the previous committed entry.

Resubmit the same index after an uncertain acknowledgment. A per-window transaction lock and unique event key serialize retries, cancellations and concurrent samplers. Late observation requests record a terminal missed slot. An operator can use `paper cancel FIRST_MS` to stop before the next settlement. Run `paper report FIRST_MS` to reconstruct the journal. Run `paper publish FIRST_MS` with a report writer to publish complete, missed or canceled results. The authorized endpoint is `GET /api/portfolios/{portfolio}/paper/{latest-or-id}`. The [independent verifier](../backtest/tests/paper_reference.py) accepts a complete exported experiment. It recomputes signals, all balances, individual costs, realized/unrealized P&L, turnover and drawdown with rational arithmetic.

The controlled source exercises decision timing and recovery with independently drawn prices. Exchange order-book liquidity, market returns, supplier rights and suitability for own capital require separate evidence.

## CCXT observations

Use `--observe-ccxt-fixture` with the local pilot for a nine-observation loopback run. A separate HTTP server emits a fresh synthetic BTC/USDT candle at receipt. CCXT Rust requests it using the public Binance spot kline method. The journal stores its compact parsed response privately, validates the inclusive venue close against the scheduled minute, and reuses the same mark for all three strategies. The exported report contains receipt digests, times and scoped accounting values. Its opening NAV is checked against cash plus marked inventory. Its one-minute historical VaR and expected shortfall revalue each strategy’s final BTC inventory under the eight observed minute returns at 62.5% confidence. Eight returns support this short-window accounting exercise.

For Binance, `paper freeze-binance FIRST_MS` uses the fixed market-data-only endpoint and the same sample, report and publish commands. The paper balances, trade lot, fee, spread, slippage and tick remain modeled assumptions. A failed, throttled or late read ends the experiment with explicit missing coverage. The lower-level diagnostic can still query a completed historical minute independently.

The [source-scope migration](migrations/003_source_scopes.sql) lets a data owner record the applicable basis for internal computation, private retention and operator display once in `oracle_paper.binance_scopes`. The reference can identify applicable published terms or an existing agreement. Experiments reuse the standing scope and pin its identifier and reference digest. A term can have an end date or remain effective until revoked. Application roles cannot issue or extend it. Expiry and revocation also apply to previously addressed reports through the portfolio read policy.

For an internal paper run, use the public Spot REST documentation and the terms it references. Section 27 of the Binance terms addresses internal business use. Record the owner, purpose and applicable terms in the scope reference. The pilot reads closed BTC/USDT candles through the market-data-only host, uses them in the local portfolio and serves the result to its authorized operator. The CCXT license covers the adapter software. ## Hypothetical spot portfolio risk

Open **Spot portfolio risk** in the workstation. Enter a venue, native spot pair, long quantity and signed price shock in basis points for each position. Use a common quote currency for all positions and cash. The local research calculator accepts up to eight distinct venue/pair positions and 5–100 completed minute closes. A venue outage or missing mark withholds the joint calculation. Repeat a failed evaluation with the original final open time to request the same window. Revised source data can change the result.

The authenticated server accepts JSON at `POST /api/portfolios/{portfolio}/spot-risk`. It checks the portfolio grant before reading the venues and again before returning the result. It does not store scenarios. An internal CLI accepts the same JSON on standard input. From the core workspace, run:

```sh
echo '{"cash":"100","closes":60,"confidence_bps":9500,"positions":[{"venue":"binance","pair":"SOL/USDT","quantity":"2","shock_bps":-1000},{"venue":"okx","pair":"DOGE/USDT","quantity":"100","shock_bps":500}]}' | cargo run --locked -p oracle-report-api -- spot-risk
```

Set optional `last_open_ms` to an aligned UTC opening timestamp for a specific completed minute. The latest eligible minute is the default. The model freezes hypothetical quantities at the last mark and applies each synchronized historical return vector to those exposures. It aggregates each scenario across positions before computing nearest-rank VaR and the fractional-mass tail mean. Positive tail loss means portfolio loss. A positive stress P&L means gain. Inputs and calculations use exact decimal and rational arithmetic. Hover over displayed amounts for the exact rational result. The reported sample size is one less than the close count. This is a retrospective one-minute market risk estimate with cash fixed in quote units. Liquidity costs, FX translation, leverage, collateral and nonlinear instruments need their own models. The BTC/USDT paper journal retains its frozen instrument and cost model.

## Personal paper wallet

The workstation starts each authenticated member with zero cash. In **My profile**, add a simulated deposit in its original currency. In **Baskets**, choose an amount in the basket's quote currency and confirm **Join with paper funds**. **Joined** shows applied revisions, remaining position cash, fills and redemption. My profile shows currency balances, quantities, basket returns and paged transaction history. Deposits, entries and fills are durable PostgreSQL records. Balances are never added across currencies.

Run `oracle-report-api basket-worker` with a loopback database connection in `ORACLE_DATABASE_URL` and a login belonging only to `oracle_basket_worker`. Run the web listener under the separate reader login. The local pilot starts both automatically. The worker uses read-only CCXT spot metadata and completed candles from Binance or OKX. The explicit `basket-worker-fixture` command serves generated observations in disposable checks. Use distinct databases for fixture and market observation runs.

The worker reserves user cash atomically, claims an instruction with a four-minute lease and rechecks its revision and scope before posting. An unposted lease becomes eligible after expiry. Unavailable prices keep the entire allocation pending. A later eligible revision supersedes intervening unfilled revisions. Redemption sells all held legs at a dated mark and credits the original currency wallet. Revoking access pauses future template allocations while the member retains valuation and redemption of existing holdings. A quote-currency change requires closing existing positions. Routine five-minute position marks update displayed NAV and never change holdings or generate fills.

`GET /api/profile` derives an authenticated member's totals, positions and transaction history. The activity page carries 25 entries and a lookahead. Supply the last displayed entry ID as `before` to fetch older events. `GET /api/discover/news` combines OKX announcements with RSS headlines from CoinDesk and Cointelegraph in a five-minute cache. External article links carry the publisher's title, source and publication time.

Migration 010 applies the administrator's enabled venue settings at basket settlement. A disabled venue keeps a pending allocation in cash or in its existing holdings until all required fills are eligible. Read-only marks can continue during the pause.

## Market discovery and paper spot tickets

The browser groups active, fresh Binance and OKX spot tickers by native base and quote symbol. It shows the highest last trade, the aggregate reported quote volume and the change from the highest reported opening price. Public discovery is indicative. The order ticket separately reads the selected side of the live display book through CCXT Rust on the server. Matching native symbols are treated as equivalent in this paper market. Production routing needs independently qualified asset identities, limits and account-specific fee schedules.

`POST /api/paper/spot` accepts a quote instruction with `pair`, `side` and a decimal-string `quantity`. An eligible level must cover the whole quantity, pass the active instrument and step checks and meet the timing limits. Buys use the highest eligible ask as the customer price and route by the lowest total cost. Sells use the lowest eligible bid and route by the highest net proceeds. A single eligible venue produces zero spread. The pilot charges a modeled taker fee of 10 basis points on the venue notional, rounded to eight quote decimal places. The customer sees the accepted price, fee, included gross paper spread and total before confirmation. Routing venue, book evidence and venue price are retained internally in PostgreSQL.

A confirmation contains only the ticket ID. The database checks owner, expiry, enabled venue and available balance, then settles cash and holdings atomically. Retrying a confirmed ticket returns its original receipt. The independent SQL case passes a five-dollar fee on a one-BTC buy at 54,999 USD against a 55,000 USD customer price. The customer pays 55,005 USD and Eighred's gross simulated spread is 1 USD. Stock is marked at the last simulated venue fill with its observation time in the wallet. Fees and spread in this model are denominated in the actual quote unit. USDT is never translated to USD on the ledger.

## Member community

Migration 009 exposes read-only published basket details, sorted by official pin and the number of distinct other members with active funding. Private invitations also accept verified handles. Published trader profiles, photos, follows and moderated posts use the authenticated community endpoint. The public profile opt-in defaults off. Each visibility change applies to future reads of existing posts. Portfolio ranking requires separate consent. For each quote currency the ranking uses lifetime net gains divided by cumulative paper deposits. The start date and calculation time are visible. Stale marked positions and accounts without trades are excluded. Ranking entries share the same numeric rank for an equal unrounded return. Member paper gains, company spread and real receipts remain distinct.
